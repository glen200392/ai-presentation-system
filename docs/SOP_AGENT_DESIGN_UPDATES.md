# SOP: Agent 設計更新標準流程
## Standard Operating Procedure for Agent Design Updates

**文檔版本**: 1.0  
**創建日期**: 2026-01-31  
**適用範圍**: 所有 Custom AI Agent 的設計變更與更新  
**負責人**: Digital Transformation Lead  

---

## 📋 目的與範圍

### 目的
建立一套標準化的 Agent 設計更新流程，確保：
1. 設計變更經過充分研究和驗證
2. 更新過程可追溯、可重現
3. 文檔完整記錄，便於未來參考
4. 知識沉澱，避免重複工作

### 適用範圍
- Custom AI Agent 的工作流程改進
- Agent Prompt 的重大更新
- Agent 工具配置的變更
- Agent 品質標準的調整

### 不適用範圍
- 日常 Agent 使用和調用
- 簡單的參數微調
- 臨時性的測試變更

---

## 🔄 標準流程（7 個階段）

### 階段 1: 需求分析與設計

**目標**: 明確更新需求，設計改進方案

#### 1.1 問題診斷
**任務**: 分析現有流程的問題
- 收集用戶反饋和痛點
- 分析現有 Agent 的性能數據
- 識別根本原因（而非表面症狀）

**產出**:
```markdown
## 問題診斷

### 現象描述
[用戶遇到的具體問題]

### 根本原因
[為什麼會發生這個問題]

### 影響範圍
[影響了哪些用戶、多少頻率]

### 量化指標
- 首次滿意度: X%
- 平均修改輪次: X 輪
- 平均耗時: X 分鐘
```

#### 1.2 改進方案設計
**任務**: 設計具體的改進措施
- 參考業界最佳實踐（如 McKinsey、BCG 標準）
- 設計新的工作流程
- 定義品質標準和檢查點

**產出**:
```markdown
## 改進方案

### 核心改進項目
1. [項目 1]: [具體措施]
2. [項目 2]: [具體措施]
...

### 新工作流程
[階段 1] → [階段 2] → [階段 3] → [階段 4]

### 預期效果
| 指標 | 改進前 | 改進後 | 提升 |
|------|--------|--------|------|
| ... | ... | ... | ... |
```

**檢查點**:
- [ ] 問題根因已明確識別
- [ ] 改進方案具體可執行
- [ ] 預期效果可量化衡量

---

### 階段 2: 需求文檔撰寫

**目標**: 撰寫完整的改進需求文檔

#### 2.1 文檔結構
**必須包含的章節**:
1. 改進摘要（問題 vs 解決方案）
2. 新工作流程設計
3. 具體實施要求（每個改進項目的詳細說明）
4. 品質檢查清單
5. 常見錯誤防範
6. 預期效果追蹤

**檔案命名規範**:
```
[AGENT_NAME]_WORKFLOW_IMPROVEMENT.md
例如: POWERPOINT_WORKFLOW_IMPROVEMENT.md
```

#### 2.2 撰寫要點
- 使用清晰的標題層級結構
- 提供具體的範例和反例
- 包含可執行的檢查清單
- 定義量化的成功指標

**產出**: `docs/WORKFLOW_IMPROVEMENT.md`

**檢查點**:
- [ ] 文檔結構完整清晰
- [ ] 每個改進項目都有具體說明
- [ ] 包含可執行的檢查清單
- [ ] 定義了量化的成功指標

---

### 階段 3: 更新指令準備

**目標**: 準備給 Agent 的詳細更新指令

#### 3.1 指令內容
**必須包含**:
1. 任務概述（目標、優先級、完成時間）
2. 6 大核心更新項目的詳細說明
3. 實施要求（工具使用、配置變更）
4. 驗證標準（如何確認更新成功）
5. 實施後報告要求

**檔案命名規範**:
```
agent_update_instructions.md
```

#### 3.2 撰寫要點
- 使用「執行指示」的語氣，而非「建議」
- 提供完整的範例和模板
- 包含驗證清單和測試案例
- 說明實施後需要回報的內容

**產出**: `tmp/agent_update_instructions.md`

**檢查點**:
- [ ] 指令清晰、可執行
- [ ] 包含完整的範例
- [ ] 定義了驗證標準
- [ ] 說明了回報要求

---

### 階段 4: 委派執行

**目標**: 將更新任務委派給目標 Agent

#### 4.1 查找目標 Agent
**步驟**:
```
1. 使用 lookup_agents(command="search", query="[agent capability]")
2. 確認 agent_id 正確
3. 使用 lookup_agents(command="details", agent_id="agt_xxx") 獲取詳細資訊
```

#### 4.2 委派任務
**步驟**:
```python
delegate(
    agent_id="agt_xxx",
    description="[精簡的任務描述，包含關鍵要求]",
    files=["tmp/agent_update_instructions.md"]
)
```

**委派描述範本**:
```markdown
# [Agent Name] 工作流程重大更新任務

## 任務目標
實施專業級工作流程改進，從根本上解決[核心問題]。

## 核心更新項目
1. [項目 1]: [簡要說明]
2. [項目 2]: [簡要說明]
...

## 執行要求
1. 更新 System Prompt，整合新工作流程
2. 配置工具使用規則
3. 執行測試驗證
4. 回報：更新的 prompt、測試結果、文檔清單

## 預期效果
[量化指標表格]

詳細說明請參考附件。立即執行並回報結果！
```

**產出**: Delegation 執行成功，獲得 Agent 回報

**檢查點**:
- [ ] Agent ID 確認無誤
- [ ] 委派成功執行
- [ ] 收到 Agent 的完整回報

---

### 階段 5: 驗證與收集

**目標**: 驗證更新結果，收集配置資訊

#### 5.1 驗證更新結果
**檢查項目**:
- Agent 是否完成了所有核心更新項目
- 是否創建了補充文檔
- 測試計畫是否完整
- 驗證標準是否達成

#### 5.2 收集配置資訊
**需要收集**:
1. 更新後的 Agent 配置摘要
2. 關鍵 Prompt 片段
3. 創建的補充文檔清單
4. 測試計畫和驗證結果

**產出**: `docs/agent_configuration_summary.md`

**檢查點**:
- [ ] 更新結果符合預期
- [ ] 配置資訊完整收集
- [ ] 創建配置摘要文檔

---

### 階段 6: 文檔更新與同步

**目標**: 更新本地文檔，同步到 GitHub

#### 6.1 更新需求文檔
**任務**: 在原始需求文檔末尾加入「實施狀態報告」
- 實施完成日期和執行者
- 核心發現（現有配置狀態）
- 6 大更新項目完成狀態
- 新增補充文檔清單
- 關鍵改進亮點
- 預期效果驗證
- 測試計畫
- 持續改進路徑

**產出**: 更新 `docs/WORKFLOW_IMPROVEMENT.md`

### 1. 問題診斷要深入

- ✅ 深入分析根本原因
- ✅ 用數據支持診斷結論

### 2. 改進方案要具體
- ❌ 不要使用模糊的描述
- ✅ 提供可執行的步驟
- ✅ 包含具體的範例和模板

### 3. 指令要清晰完整
- ❌ 不要假設 Agent 知道背景
- ✅ 提供完整的上下文

- ❌ 不要只檢查部分項目

## 📞 常見問題

### Q1: 什麼情況需要走完整流程？
**A**: 當 Agent 的工作流程或品質標準需要重大變更時。例如：
- 需要新增強制執行的階段
- 品質標準需要全面提升
- 工具使用方式需要根本改變

### Q2: 如果只是小調整需要走完整流程嗎？
**A**: 不需要。小調整（如參數微調、簡單話術調整）可以直接執行。完整流程適用於「會影響用戶體驗的重大變更」。

### Q3: 委派給 Agent 後發現問題怎麼辦？
**A**: 
1. 記錄具體問題
2. 調整更新指令
3. 重新委派執行
4. 在文檔中記錄調整過程

### Q4: 如果 Agent 回報現有配置已滿足需求？
**A**: 
1. 確認 Agent 的分析是否正確
2. 檢查是否只需要補充文檔
3. 更新需求文檔的實施狀態
4. 推送補充文檔到 GitHub

### Q5: GitHub 推送失敗怎麼辦？
**A**: 
1. 檢查檔案路徑是否正確
2. 確認 GitHub 連接狀態
3. 檢查檔案是否已存在（需要 SHA）
4. 查看錯誤訊息並調整

## 📊 成功案例

### 案例: PowerPoint Agent v2.0 升級

**背景**: 用戶反映簡報需要多輪修改，首次滿意度僅 40%

**執行**:
- 階段 1-2: 完成問題診斷和需求文檔（2 小時）
- 階段 3-4: 準備指令並委派執行（30 分鐘）
- 階段 5: Agent 回報現有配置已含 90% 功能（驚喜發現）
- 階段 6-7: 更新文檔並推送（1 小時）

**結果**:
- ✅ 完成度 98%
- ✅ 新增 8 份專業文檔（96 KB）
- ✅ 預期首次滿意度提升 100%
- ✅ 總時間節省 85 分鐘

**關鍵學習**:
1. 委派前要明確指令，Agent 才能充分發揮
2. 現有配置可能已經很好，重點是文檔化
3. 補充文檔比修改 Prompt 更有效
