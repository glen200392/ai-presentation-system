# PowerPoint Agent 大綱批准流程詳細指南

## 🎯 目的
確保生成的簡報 100% 符合用戶期望，避免「生成後大幅修改」的問題。

---

## 📋 大綱必須包含的 7 個要素

### 1. 基本資訊摘要
```markdown
## 📊 簡報規格

- **主題**：[簡報標題]
- **目標受眾**：[投資人/管理層/...]
- **使用目的**：[融資/戰略/...]
- **品質等級**：[職場頂級級 - 85%品質標準]
- **預計時間**：[2.5小時生成時間]
- **總頁數**：[15-18頁]
- **視覺風格**：[McKinsey商務正式]
```

### 2. 整體架構樹狀圖
```markdown
## 🏗️ 簡報架構

開場 (2頁)
├─ 封面
└─ 執行摘要

第一部分：市場洞察 (5-6頁)
├─ 市場規模與增長
├─ 關鍵驅動因素
├─ 競爭態勢分析
└─ 機會與挑戰

第二部分：戰略建議 (4-5頁)
├─ 核心策略
├─ 差異化優勢
└─ 實施路徑

結尾 (2-3頁)
├─ 財務預測
├─ 風險評估
└─ 下一步行動
```

### 3. 每頁結論型標題（McKinsey 風格）
```markdown
## 📄 詳細頁面標題

### 開場 (2頁)
1. [封面] [主題名稱] - [副標題]
2. [執行摘要] 三大發現：市場爆發、競爭加劇、策略轉型迫在眉睫

### 第一部分：市場洞察 (5-6頁)

3. **台灣健檢市場達 700 億，年增 7% 創十年新高**
   - 關鍵數據：2024 年市場規模、增長率、預測值
   - 視覺元素：大數字展示 + 十年趨勢圖
   - So What：市場正處於快速擴張期，是進入的最佳時機

4. **疫後復甦推動需求爆發，高階健檢占比提升至 35%**
   - 關鍵數據：2020-2024 疫情前後對比、高階健檢增長率
   - 視覺元素：堆疊長條圖（基礎/中階/高階）
   - So What：消費升級趨勢明確，應聚焦高端市場

5. **三大趨勢重塑市場：預防醫療、精準健康、個人化服務**
   - 關鍵論點：每個趨勢的驅動因素和市場影響
   - 視覺元素：三欄對比 + 圖示
   - So What：技術創新創造新商機

[繼續列出所有頁面...]
```

### 4. 關鍵訊息流（說服邏輯）
```markdown
## 🎯 關鍵訊息流（McKinsey 金字塔原理）

**核心論點**：現在是進入台灣健檢市場的最佳時機

**支持論據 1**：市場規模大且增長快（第 3-4 頁）
  ├─ 數據證明：700 億市場、7% 年增
  └─ 趨勢證明：疫後需求爆發，高階化趨勢

**支持論據 2**：競爭格局仍有空間（第 5-6 頁）
  ├─ 現有玩家分析：傳統醫院主導，新創機會
  └─ 差異化可能：技術創新、服務升級

**支持論據 3**：我們有獨特優勢（第 7-10 頁）
  ├─ 技術優勢：AI診斷、精準健康
  ├─ 服務優勢：個人化、便利性
  └─ 商業模式：訂閱制、會員制

**結論**：立即行動，搶佔先機（第 15-18 頁）
  ├─ 進入策略：從高端市場切入
  ├─ 實施路徑：6 個月試點、12 個月擴張
  └─ 財務預測：3 年達損益平衡、5 年 ROI 200%
```

### 5. 視覺設計規範預覽
```markdown
## 🎨 視覺設計規範

**配色方案**
- 主色：McKinsey 藍 (#003D7A) - 標題條、主要圖表
- 強調色：商務橘 (#FF6B35) - 關鍵數字、重點標註
- 輔助色：深灰 (#4A4A4A) - 內文文字
- 背景：淺灰 (#F5F5F5) - 區塊背景

**字體系統**
- 標題：Calibri Bold 36pt（或微軟正黑體 Bold 32pt 中文）
- 副標題：Calibri 24pt
- 內文：Calibri 18pt（或微軟正黑體 16pt 中文）
- 關鍵數字：Calibri Bold 56pt + 強調色

**排版標準**
- 頁面邊距：上下左右 0.75 英吋
- 標題條高度：1.0 英吋
- 內容起始位置：距頂部 2.2 英吋
- 圖表高度：4.5-5.2 英吋（根據類型調整）
- 物件間距：0.8 英吋（圖表到文字）

**圖表規範**
- 每頁最多 1 個大型圖表或 2 個中型圖表
- 所有圖表包含：標題、座標軸標籤、數據來源
- 關鍵數據點使用強調色標註
- 避免 3D 效果和過度裝飾
```

### 6. 品質保證承諾
```markdown
## ✅ 品質保證清單

### 內容品質
- [x] 100% 使用結論型標題（非主題型）
- [x] 每頁包含「So What」洞察（不只是數據展示）
- [x] 金字塔原理邏輯結構（結論先行）
- [x] 所有數據標註來源

### 視覺品質
- [x] 關鍵數字使用 56pt + 強調色
- [x] 每頁有明確視覺焦點（不平均分配注意力）
- [x] 排版參數符合 McKinsey 標準（0.75" 邊距）
- [x] 配色專業一致（不超過 3 個主色）

### 專業度
- [x] 無錯別字和語法錯誤
- [x] 數據前後一致（同一數字在不同頁面的表述一致）
- [x] 符承諾的品質等級（85% 職場頂級標準）
- [x] 邏輯清晰、說服力強
```

### 7. 風險提示與限制說明
```markdown
## ⚠️ 風險提示

**資料限制**
- 部分數據可能需要用戶提供（如內部數據、專有研究）
- 公開數據可能存在時間延遲（最新數據為 2024 年 Q3）
- 某些產業數據需要付費報告才能取得

**技術限制**
- 複雜動畫無法程式化生成（將提供手動實作指南）
- 自訂字型需用戶電腦已安裝
- 圖表美化可能需要手動微調

**時間估算**
- 預計生成時間：2.5 小時
- 如需額外網路搜尋：+30 分鐘
- 如需複雜圖表：+45 分鐘

**調整彈性**
- 大綱批准後，內容架構不建議大幅調整
- 小幅修改（如單頁內容）可快速執行
- 風格調整（如配色）可在生成後修改
```

## 🔄 批准流程步驟

### Step 1: 展示完整大綱
向用戶展示包含以上 7 個要素的完整大綱。

### Step 2: 詢問確認
使用以下標準話術：

```markdown
## 🔍 請您確認大綱

我已根據您的需求設計了完整的簡報架構（如上）。

請確認以下幾點：

1. **內容架構** - 章節劃分和邏輯流程是否合理？
2. **頁數與深度** - 總頁數 [X] 頁是否合適？內容深度是否足夠？
3. **標題風格** - 結論型標題是否符合您的偏好？
4. **視覺設計** - 配色和排版風格是否合適？
5. **關鍵訊息** - 說服邏輯是否清晰有力？

**回覆選項**：
- ✅ **確認無誤，開始生成** - 我將立即按此大綱製作簡報
- 🔧 **需要調整** - 請告訴我需要修改的地方（例如：增加某章節、調整順序、改變風格）
- ❓ **有疑問** - 請告訴我您想了解的細節

**預計完成時間**：[X] 小時後交付完整簡報
```

### Step 3: 處理反饋

#### 情況 A：用戶確認無誤 ✅
```markdown
太好了！我將立即開始製作簡報。

進度追蹤：
1. [進行中] 收集資料與數據（預計 30 分鐘）
2. [等待中] 生成圖表（預計 45 分鐘）
3. [等待中] 組裝簡報（預計 60 分鐘）
4. [等待中] 品質檢查（預計 15 分鐘）

我會在完成後第一時間通知您！
```

#### 情況 B：用戶要求調整 🔧
```markdown
了解！讓我根據您的反饋調整大綱。

您希望調整的地方：
- [列出用戶的修改需求]

我的建議：
- [如果有更好的替代方案，提出建議]

調整後的大綱：
[展示修改後的版本]

請確認這樣是否符合您的需求？
```

#### 情況 C：用戶有疑問 ❓
```markdown
很高興為您解答！

關於 [用戶的問題]：
[詳細解釋設計考量、為什麼這樣安排、有什麼替代方案]

如果您認為應該調整，我可以立即修改大綱。
```

### Step 4: 重複確認（如有調整）
如果大綱經過修改，必須再次展示完整版本並等待確認。

**禁止**：
- ❌ 假設用戶同意，直接開始生成
- ❌ 只展示修改的部分，不展示完整大綱
- ❌ 跳過二次確認

---

## 🚨 強制執行規則

### ⛔ 絕對禁止：

1. **未經批准開始生成**
   - 即使大綱看起來完美，也必須等待明確批准
   
2. **大綱過於簡略**
   - 必須包含所有 7 個要素，不能只列標題
   
3. **不說明設計考量**
   - 用戶需要理解「為什麼這樣設計」
   
4. **假設用戶理解專業術語**
   - 如「SCQA」、「金字塔原理」需要簡單解釋

### ✅ 必須做到：

1. **展示完整大綱**
   - 所有頁面標題、關鍵訊息流、視覺規範
   
2. **提供清晰的確認選項**
   - 讓用戶容易回覆
   
3. **解釋設計邏輯**
   - 為什麼這樣安排章節？為什麼選這個標題？
   
4. **允許多輪調整**
   - 不限制調整次數，直到用戶滿意

## 📊 批准流程品質檢查

開始生成前，確認：
- [ ] 已展示包含 7 個要素的完整大綱
- [ ] 已詢問用戶確認
- [ ] 用戶已明確回覆「確認無誤」或類似表述
- [ ] 如有調整，已重新展示並確認
- [ ] 用戶理解預計完成時間和交付內容

## 🔄 持續改進

### 追蹤指標
- 大綱一次通過率（目標：70%+）
- 平均調整輪次（目標：≤2 輪）
- 用戶滿意度（大綱階段，目標：85%+）

### 學習機制
- 記錄哪些類型的大綱最常被調整
- 分析調整的主要原因（架構/標題/深度/風格）
- 優化初次大綱生成的準確性

### 反饋收集
生成完成後，詢問：
- "大綱批准流程是否清晰？"
- "是否有改進建議？"
- "哪些資訊最有幫助？"
